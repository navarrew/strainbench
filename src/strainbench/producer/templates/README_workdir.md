# strainbench annotation workdir

This directory was generated by `strainbench annotate-prep`. It contains the
cluster representative sequences plus ready-to-run shell scripts for each
annotator strainbench knows how to import.

## What's here

- `reps.faa` — one protein sequence per cluster representative. Record IDs
  are the cluster names. This is the input to every annotator.
- `eggnog.sh` — eggNOG-mapper (COG + KEGG + GO + Pfam + EC + CAZy, one tool).
- `kofamscan.sh` — kofamscan (KEGG KOs with precise thresholds).
- `deepnog.sh` — DeepNOG (COG group prediction via neural network).
- `amrfinder.sh` — NCBI AMRFinderPlus (AMR / stress / virulence genes).
- `defensefinder.sh` — DefenseFinder (antiphage defense systems).
- `padloc.sh` — PADLOC (independent antiphage defense identifier;
  complementary to DefenseFinder).
- `interproscan.sh` — InterProScan (domain-level annotation from
  Pfam/TIGRFAM/PANTHER/etc.; heavyweight — install + 1–2 hr per run).
- `.strainbench_workdir.json` — internal manifest; don't edit.

## How to use this directory

### 1. Configure once per machine

Each script reads environment variables so you don't have to edit the
scripts themselves. Add to your shell profile (`~/.zshrc` or `~/.bashrc`)
the paths that apply to your setup:

```bash
export EMAPPER_DATA_DIR=$HOME/databases/eggnog-v6
export KOFAM_PROFILES=$HOME/databases/kofam/profiles
export KOFAM_KO_LIST=$HOME/databases/kofam/ko_list
```

DeepNOG ships its own models — no path configuration needed.

### 2. Run whichever annotators you want

Each tool lives in its own conda env because their dependencies conflict.
Run them one at a time:

```bash
conda activate emapper        && bash eggnog.sh
conda activate kofam          && bash kofamscan.sh
conda activate deepnog        && bash deepnog.sh
conda activate amrfinder      && bash amrfinder.sh
conda activate defensefinder  && bash defensefinder.sh
conda activate padloc         && bash padloc.sh
# InterProScan is heavyweight — only run if you need domain-level resolution:
bash interproscan.sh
```

The scripts do pre-flight checks and tell you exactly what's wrong if a
database path is misconfigured or the conda env isn't active.

### 3. Import all outputs with one command

Back in the strainbench env:

```bash
conda activate strainbench
cd ..  # back to the dir with your .db file
strainbench import-annotation --db your.db --workdir path/to/this/dir
```

strainbench auto-detects each output file's format and imports all of them.

### 4. Re-export your spreadsheet

```bash
strainbench export-xlsx --db your.db -o cluster_table.xlsx
```

New columns appear automatically for whichever annotation sources you ran.

## Re-running a year later?

The same directory works — strainbench records each annotation's `source_file`,
so `strainbench status --db your.db` will tell you which annotations came
from which file and when. To update: re-run the scripts here, then:

```bash
strainbench import-annotation --db your.db --workdir . --replace
```

The `--replace` flag deletes old annotations of the same source before
inserting the new ones, preventing duplicates.
